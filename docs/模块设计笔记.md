# 星途学堂 · 模块设计笔记

按课程模块整理的设计要点与实现思路，用于复盘微服务场景下的典型问题与解法。

## 1. 项目结构与开发模式

- 服务按业务域拆分，父工程统一依赖版本（`tj-parent`），`xt-common` 放通用工具、异常、拦截器与自动配置。
- 企业开发模式下不是所有模块都能拉到本地：模块之间通过 API 模块 + Feign 接口约定通信，本地只跑自己负责的服务，其他服务用 Mock 或公共环境。
- 测试分层：单元测试 → 集成测试（验证单个接口）→ 组件测试（验证微服务组件）→ 端到端联调。

## 2. 我的课表

- 用户购买 / 加入课程后生成 `learning_lesson` 记录，课表按 `plan_status`（学习中、已学完、已过期）与 `lesson_status` 分类展示。
- 课表查询需要「课程信息 + 学习状态」两处数据，课程信息由课程服务提供，学习服务通过 Feign 聚合，避免跨库连表。

## 3. 学习计划与学习进度

- 播放进度上报频率极高（每几秒一次），直接写库会造成大量无效 IO。
- 方案：**先写 Redis，再延迟合并落库**。
  - `LearningRecordFormDTO` 接收上报，按 `lessonId + sectionId` 存到 `xt:learning:record:{lessonId}` 的 Hash 中；
  - 用 `DelayQueue` + `DelayTask`（实现 `Delayed`）承载延迟任务，到点由后台线程取出；
  - `LearningRecordDelayTaskHandler` 在 `@PostConstruct` 启动异步消费线程，`@PreDestroy` 置标志位停止，保证优雅关闭；
  - 落库时判断是否需要更新课表状态（学完 / 过期）。
- 学完一节后按 `SectionType` 判断该小节类型，决定是否推进课表进度。

## 4. 互动问答

- `xt_learning_question` 存问题主体，回答与评论走文档型存储（MongoDB）更适合这种嵌套、变长的结构。
- 列表页需要「问题 + 最新回答 + 回答数」，用聚合查询 + 缓存减少重复查询。

## 5. 点赞系统

- 点赞是高频写、允许最终一致的场景：计数放 Redis（Hash 按业务类型 + 业务 id 聚合），用户是否点赞用 Set 去重。
- 定时任务批量把 Redis 计数同步到数据库（`xt_remark` 表），避免每次点赞都写库。
- `LikedTimesDTO` 用于服务间批量同步点赞数。

## 6. 积分与排行榜

- 签到、学习、问答等行为产生积分，写入 `points_board` 流水表。
- 排行榜用 Redis ZSet 实现：`ZINCRBY` 累加积分，`ZREVRANGE` 取前 N 名，按天 / 周 / 赛季分 key，历史榜单落库。

## 7. 优惠券

- 管理端创建优惠券：类型分为**无门槛、满减、每满减、折扣率**，各自有校验规则与折扣算法。
- 用策略模式隔离算法：`Discount` 接口 + 四个实现，`DiscountStrategy` 用 `EnumMap<DiscountType, Discount>` 注册，调用方只按类型取策略，新增券类型不改调用方代码。
- 领取环节要防超发：库存判断与扣减放在 Redis + Lua 脚本里做原子操作。
- 使用时计算最优优惠：先筛出可用券（门槛、有效期、适用课程、是否互斥），再对可用券组合求解，`PermuteUtil` 生成组合、逐组算价取最大优惠。

## 8. 高并发优化

- 用 JMeter 压测提交学习记录接口，观察吞吐与数据库压力。
- 优化手段：合并写（同一小节短时间多次上报只落最后一次）、异步落库、加缓存、减少事务范围。
